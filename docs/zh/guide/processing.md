# 处理队列

识别在队列中进行，每段视频运行一次姿态模型。之后的一切（质控、评分、复核）都基于保存的关键点，不再需要模型。

## 处理队列页

在侧栏打开 **处理队列**（⌘2）。它显示：

- 正在识别的视频画面（约每秒一次），画有关键点；
- 进度、每秒帧数，以及这段视频和整个队列的剩余时间；
- 每段视频使用哪个模型，哪些视频在等待、失败或离线。

可以**暂停**（⌘.）和**开始**（⌘R）队列，把视频移到最前或最后（⌥⌘↑ / ⌥⌘↓），以及取消单个视频。同时识别 1–3 段视频（设置 › 处理中的*同时处理的视频数*）。**重试失败的视频**把失败的视频重新排入队列，每段都从检查点继续。Dock 图标显示总进度，队列完成时会收到通知。

所有视频识别完成后，这一页会说明并给出下一步：需要做 QC 决定的视频（**立即复核**）、已纳入但没有任务的视频（**分配任务…**）以及已就绪的分析（**打开分析**）。

## 为什么批处理不会崩溃或重头再来

- **逐帧检查点。** 关键点一边计算一边写盘，至少每 2 秒一次。暂停、退出、崩溃、笔记本合盖或断电后，从最后保存的帧之后继续。续跑得到的关键点与一次跑完逐位相同。
- **一段坏视频不会让批处理停下。** 解码或 Core ML 错误会从检查点重试，最多 3 次；仍然失败的视频标为*失败*并写明原因，队列继续。无法解码的编码会立即失败，不再重试。
- **不会反复崩溃。** 如果识别同一段视频时 App 两次意外退出，这段视频会被搁置并附上说明。
- **离线硬盘。** 未连接硬盘上的视频以*离线*状态留在队列中；其他视频继续，硬盘接回后再完成它们。
- **磁盘空间。** 剩余空间少于 300 MB 时，队列暂停，而不是让视频失败。
- **退出。** 识别过程中退出会先询问；正在运行的视频停在当前帧，下次继续。关闭窗口不会退出 App，识别在后台继续。
- **睡眠与 App Nap。** 识别时 Mac 不会因闲置而睡眠（显示器仍可关闭；如需允许睡眠，在设置中关闭*识别时保持 Mac 唤醒*），App 也不会被 App Nap 降速。
- **内存稳定。** 内存中只保留关键点，因此几小时长的视频也不会让内存增长。

每次导入、每段视频、每次失败和恢复都写入活动日志（**显示活动日志**）。

## Intel 与 Apple 芯片

两者都支持，得到相同的关键点。Apple 芯片在神经网络引擎上运行模型，快得多。在 Intel Mac 上，半精度模型输出会逐位转换，数值完全相同。
