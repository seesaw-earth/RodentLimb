# RodentLimb for Mac（1.4.2）— 从这里开始

RodentLimb 的 Mac 版。它和 iPhone 版 RodentLimb 1.4 用同样的两个姿态模型、同一套分析代码，资料库文件格式也一样。同一段视频在两端得到相同的关键点和相同的指标。Mac 版主要为**批量处理大量长视频**设计：放一晚上不用管，第二天看结果、复核、一次导出。

> **本代码包没有在 Xcode 中编译过**（这里没有 macOS SDK）。不依赖界面的核心层在 Linux 上用 Swift 6.0 编译，并通过了自动测试（见“验证”）。界面代码做过语法检查和逐行审阅。请先在 Xcode 中编译一次，有报错把错误信息发给我。

---

## 1. 打开与运行

1. 用 **Xcode 16 或更新版本**（推荐 Xcode 26/27）打开 `macOS/RodentLimb.xcodeproj`。
2. Target **RodentLimb** › Signing & Capabilities › 选择你的 Team（工程里已填 `5Y62DWN7RS`）。
   - Bundle ID 为 `com.ziqingshi.rodentlimb`，与 iPhone 版相同。这样可以在 App Store Connect 的同一条 App 记录里 *Add Platform → macOS*，实现 Universal Purchase（一次购买，两端可用）。
3. ⌘R 运行。最低系统 **macOS 14 Sonoma**；Apple 芯片和 Intel 都能运行，Apple 芯片快得多。
4. 两个模型已经放在 `macOS/RodentLimbMac/Models/`（`CylinderPose7_FP16_640.mlpackage`、`PalmReaderPose8_640_W8A16.mlpackage`），Xcode 会自动编译进 App。换新模型时运行 `python3 tools/install_model.py --fp16 <模型>` 或 `--nir <模型>`。可选的抓挠分类模型用 `tools/install_scratch_model.py` 安装，用法与 iPhone 版相同。

工程用 Xcode 16 的“文件夹同步”：`macOS/RodentLimbMac/` 和 `Shared/` 里的文件会自动加入 target，不需要手动拖入。

## 2. 工作流程：先选任务，再处理视频

与 RodentFlow（build 11）相同的思路：**任务 → 组别 → 动物 → 会话**。一个任务就是用一种范式做的一次实验（例如“步态 · SNI 第 2 批”），所有视频都在任务里添加、处理、复核和比较。

| 步骤 | Mac 上怎么做 |
|---|---|
| **1. 新建任务** | ⇧⌘N，或工具栏“新建任务”、侧栏“任务”旁的“新建”。先选范式（按用途分组：运动——步态、圆筒；疼痛与瘙痒——瘙痒、自发痛；情绪与刻板行为——悬尾、理毛；癫痫——癫痫评分），再填名称（默认“范式 + 日期”）、组别（如 Sham、SNI，可留空）、时间点（可选）、备注和是否盲法。 |
| **2. 添加视频** | 在任务页点“添加视频…”（⌘O），或把视频 / 文件夹**直接拖进窗口**（没有选中任务时会先新建任务）。表格里逐个视频确认：动物编号（按文件名自动填）、**组别**（文件名或文件夹名里有组名时自动选中；任务里已有的动物保持原组别）、时间点、试次；可多选批量修改。选择**姿态模型**（可见光 FP16（默认）/ 近红外暗箱）。读不了的格式（AVI、MKV、这台 Mac 没有解码器的 AV1 等）会提前提示并给出转换方法；同一文件重复添加会被识别出来。添加后每段视频立刻成为任务里的一个**会话**。 |
| **3. 处理（姿态识别）** | 自动排队，每个视频只跑一次模型。会话列表的“状态”列直接显示“识别中 45%”；“处理队列”页显示实时画面和关键点、进度、帧率、剩余时间和整批的预计完成时间，可暂停、继续、调整顺序或取消单个视频。Dock 显示总进度，完成后发通知。 |
| **4. QC 与纳入** | 质量检查与 iPhone 版相同。达标的视频自动纳入；其余在“待复核”中等待你的决定（任务页会显示数量）：**I** 纳入，**E** 排除（需选原因），**↓/↑** 切换。排除的会话仍显示在任务里（标为“已排除”），不计入组间结果。 |
| **5. 结果** | 任务页三个标签：**会话**（按组别、动物、时间点、试次排列，显示状态和关键指标，双击打开会话）、**结果**（组间比较：每只动物一个点、组均值 ± 标准误、n 按动物计；多个时间点时显示各组时间进程；完整性表格；排除及原因）、**设计**（组别与动物、随机分组、盲法、QC 标准、方法学文字、删除任务）。侧栏里展开任务可直接选某一组，任务页只显示该组。单个会话页分摘要、复核、全部指标三个标签；参数在右侧检查器中修改并实时重算，“复制参数到所选”时每个视频保留自己的注射时刻和注射爪。需要标定的范式（圆筒、步态）在标定窗口中进行，可“用于本任务所有会话”。 |
| **6. 导出** | ⌘E 或任务页“导出…”：导出当前任务（或所选会话 / 整个资料库），结构见第 4 节。 |

侧栏下方的“列表”跨任务显示：处理队列、待复核、失败、全部视频，以及“未归入任务”（旧版本导入、或从任务中移出的视频；右键“移到任务…”即可放进某个任务）。

**旧资料库照常打开**：1.3 及以前的研究（包括 iPhone 上建的研究）按范式显示为任务；一个研究分析过几种范式就显示为几个任务（“研究名 · 步态”“研究名 · 圆筒”），共用组别和动物。没有范式的研究显示在“未归入任务”页，选一个范式即可变为任务。文件格式没有改变，iPhone 与 Mac 可以继续交换资料库。

### 窗口与布局（1.4.1）
- 主窗口最小 860 × 560，13 英寸 Mac 用“更大字体”显示设置时也放得下；默认大小按屏幕计算，不会超出屏幕。
- 所有弹出窗口（添加视频、新建任务、导出、移到任务、标定、编辑设计等）按“窗口工具栏以下到屏幕底部”的可用空间限制高度，内容可滚动，确定 / 取消按钮固定在底部，任何屏幕上都点得到。
- 窗口变窄时页面自动改为上下排列：任务页标题和按钮、视频页的决定栏、复核页的视频与事件列表、处理队列的控制按钮；计数和标签自动换行。窗口宽度小于约 1040 时自动隐藏右侧检查器，拉宽后恢复。
- 视图切换（会话 / 结果 / 设计，摘要 / 回放 / 全部指标）放在页面里，不放在工具栏；工具栏只保留“新建任务”和“识别 / 暂停”，以及各页最常用的一两个操作，窄窗口时多余项进入系统的溢出菜单。
- 1.4.2：窗口的最小尺寸固定为 860 × 560，不随页面内容变化（页面放不下时在页面内滚动）。以前内容的最小尺寸会传给窗口，可能引发 AppKit 反复重排窗口并闪退（日志：“Update Constraints in Window passes”）。识别时的进度更新也不再让整页或侧栏反复重排。

## 3. 批处理为什么不会崩、不会白跑

- **逐帧写盘的检查点**：识别时每一帧的关键点都写进 `Recordings/<id>/checkpoint/`，至少每 2 秒落盘一次。暂停、退出、合盖休眠、App 崩溃或断电，最多丢最后几秒；再次开始时从最后一行完整记录之后继续，写了一半的行会被丢掉。续跑得到的结果与一次跑完的结果**逐位相同**（自动测试已验证）。
- **一个视频出问题不会拖垮整批**：解码出错、Core ML 偶发错误这类问题，会从检查点自动重试，最多 3 次。仍然失败的视频标为失败并写明原因，队列继续处理下一个。
- **防死循环**：崩溃日志记录每个视频开始和结束的时间。如果同一个视频运行时 App 两次意外退出，下次启动会把它搁置并说明原因，避免通宵批处理反复崩在同一个坏文件上。
- **视频不在也不会失败**：移动硬盘或网络盘没连接时，这些视频留在队列里，标为“视频离线”，先处理其他视频。硬盘接回后会自动继续。也可以用“定位视频…”重新指定路径。指纹由文件大小、修改时间和首尾各 1 MB 组成，如果文件被替换，会提示并重新识别。
- **磁盘空间不足时暂停**：可用空间少于 300 MB 时，队列自动暂停，不会把视频标为失败。
- **退出时先确认**：识别进行中按 ⌘Q 会先询问。确认后，正在跑的视频在当前帧停下并保存，下次打开时从该处继续。关闭窗口不会退出 App，识别会在后台继续。
- **防休眠与 App Nap**：识别期间阻止系统空闲休眠（可在设置中关闭，显示器仍可休眠），不会被 App Nap 降速。
- **内存稳定**：每一帧的 Vision、Core ML 和 CoreVideo 对象都在独立的 autorelease pool 中释放。内存里只保留关键点，几小时的长视频内存占用也不上涨。收到内存压力通知时会清理缓存。
- **主线程不做重活**：读写资料库、加载结果、QC、分析和导出都在后台执行；同一时刻最多运行 1–3 个视频（可设置），每个视频占一个独立线程。
- **Intel 和 Apple 芯片一致**：Intel Mac 上不能用 Swift 的 `Float16`，半精度输出改为逐位转换。全部 65536 个半精度值都测试过，与参考结果完全一致。
- 继承 iPhone 1.2.1 的稳定性修复：播放器在视频就绪前不跳转（AVPlayer 在未就绪时跳转会崩溃），读取文件时校验并修复损坏数据，NaN 不会导致保存失败，所有数值转换都做了防越界处理。

### 数据不会丢失
- **最近删除**（文件 › 最近删除…，⌥⌘⌫）：删除视频、会话或任务时，文件夹先移到资料库里的 `Recently Deleted/`，保留 30 天，可以一键恢复（视频会带着它的分析一起回来；删除任务但保留视频时，恢复任务后原来的视频会重新归入）。删除后底部提示条上有“撤销”按钮。引用的视频文件本身从不删除。
- **自动备份**：每天打开资料库时，以及删除和批量修改（批量纳入/排除、参数“应用到…”）之前，把所有任务、视频的设计信息与纳入决定、分析的参数和人工标签写入 `Backups/`（一个紧凑的 JSON 文件，保留最近 14 个每日备份 + 10 个修改前备份）。在“设置 › 高级 › 数据安全”中可以恢复：不改识别结果、不删除任何东西，恢复前会先备份当前状态。
- **随时写盘**：修改在半秒内保存；纳入/排除决定立即保存；App 切到后台、Mac 睡眠、退出、重启 App 之前都会立即保存。
- **两台 Mac 同时打开同一资料库时提醒**（共享盘、iCloud 云盘）：资料库里的 `.rodentlimb-lock.json` 每分钟刷新一次，另一台 Mac 打开时会提示，避免互相覆盖。

### 两个姿态模型：可见光 FP16（默认）/ 近红外暗箱
添加视频时（表格右侧“姿态模型”）按拍摄光线选择；在视频页面“重新识别…”时也可以换用另一个模型：

| 选项 | 模型 | 适用 | 关键点 |
|---|---|---|---|
| 第一项（默认） | CylinderPose7_FP16_640（CylinderMousePose v2.1，半精度，19 MB） | 普通室内光（可见光）下拍摄的视频 | 7 个：四爪、尾根、鼻尖、嘴 |
| 第二项 | PalmReaderPose8_640_W8A16（Ultralytics YOLO-pose，Zenodo 16321240） | 黑暗中用**近红外**光从下方拍摄的视频（暗箱 / Blackbox 类装置） | 8 个：尾根、身体中心、颈、snout、四爪 |

1.4 起不再附带 38 MB 的 CylinderMousePoseV2：CylinderPose7_FP16 是同一个训练好的网络（权重存为半精度，104 个权重张量最大相对差 0.044%）。没有记录模型的视频（iPhone 资料库、旧版本识别的视频）仍标为 CylinderMousePoseV2，结果保持不变；重新识别这些视频时使用 FP16。同一任务中请所有视频用同一个模型识别。

两个模型保存同样格式的关键点（`pose.bin` 仍为 7 个点），所有分析、QC、复核和导出都通用：近红外模型的 snout 存为鼻尖；它没有嘴部关键点，嘴保持缺失，舔爪、面部理毛等需要嘴的地方自动改用鼻尖；身体中心和颈不保存。每个视频用了哪个模型记录在 `source.json` 和 `pose.bin` 里，并写入导出（`qc_videos.csv` 的 `pose_model` 列、manifest、方法学文字、per_video 摘要）。默认选项可在“设置 › 处理 › 姿态模型”中修改。

注意：近红外模型的元数据写着尚未在设备上验证（`runtime_verified: false`）。请先用几段暗箱视频在“处理队列”的实时画面和 QC 播放器里检查关键点位置再批量使用。

### 语言（English / 简体中文）
菜单栏“RodentLimb › Language · 语言”、侧栏底部的“EN / 中文”按钮和“设置 › 通用”都可以切换，界面立即切换、不丢失当前页面和数据。macOS 自己提供的菜单（编辑、窗口、打开/存储面板）要重新启动后才会切换，App 会询问是否立即重启——重启前自动保存并停止批处理，重启后从检查点继续。导出文件始终为英文。

## 4. 数据怎么放

### 资料库（Library）
默认位置是 App 容器里的 `Documents/RodentLimb`，从菜单“文件 › 在访达中显示资料库”可以打开。也可以用“文件 › 打开资料库…”放到任意位置，例如外置硬盘上的项目文件夹。

```
RodentLimb/                      与 iPhone 版目录结构相同（可以把 iPhone 的“文件 › 我的 iPhone › RodentLimb”拷过来直接打开）
├── Experiments/<id>.json        任务（存为研究）：范式、组别、动物、时间点、盲法、QC 标准
├── Recordings/<id>/             每个视频一个文件夹
│   ├── recording.json           动物、时间点、QC 报告、纳入/排除及原因
│   ├── pose.bin                 姿态数据（与 iPhone 版格式相同，几 MB/小时）
│   ├── source.json              （Mac）视频在哪里：书签、路径、指纹；用哪个姿态模型
│   ├── checkpoint/              （Mac）识别中的检查点，完成后自动删除
│   └── thumbnail.jpg            （Mac）列表缩略图
├── Sessions/<id>/               每个会话（一个视频在任务中的分析）：session.json（参数、标定、人工修改）、result.json
├── Logs/activity-日期.log       （Mac）批处理日志：导入、每个视频、失败、恢复
├── Recently Deleted/<id>/       （Mac）最近删除：与资料库相同的结构 + entry.json，30 天后自动清除
├── Backups/metadata-<日期>-<原因>.json   （Mac）任务、视频信息和分析参数的备份
└── .rodentlimb-lock.json        （Mac）哪台 Mac 正在使用这个资料库
```

**视频默认不复制**，而是原地引用（沙盒安全书签），不会重复占用硬盘。如果需要，可以在导入时或设置中选择“复制到资料库”。

### 导出（⌘E）
```
RodentLimb_<范围>_<日期_时间>/
├── README.txt                   数据字典：每个文件、每一列是什么
├── export_manifest.json         App 和模型版本、导出选项、每个分析的参数、标定和人工修改次数
├── qc_videos.csv                每个视频的识别质量、QC 结论、纳入/排除及原因（ARRIVE 2.0 第 3 项）
├── study_<任务>_design.txt      设计与方法学文字
├── ITCH_Itch_scratching/        每个任务一个文件夹
│   ├── ITCH_summary.csv         每个分析一行：设计列和全部指标（长格式，可直接用于 R/Python/SPSS/Prism）
│   ├── ITCH_segments.csv        行为片段（最常用）：所有视频的每个事件或 bout（开始、结束、时长、注射后时间、
│   │                              自动标签、复核后标签、是否人工修改、是否计入）
│   ├── ITCH_ethogram.csv        行为谱区间
│   ├── ITCH_time_bins.csv       时间进程（长格式：分析 × 时间段 × 指标）
│   ├── ITCH_methods.txt         方法学段落（含参数和参考文献）
│   ├── ITCH_boris_events.tsv    （可选）BORIS“aggregated events”表
│   ├── frame_labels/            （可选）逐帧 0/1 行为标签（DeepEthogram / daart 格式）
│   └── per_video/               （可选）每个视频一个文件夹，内容与 iPhone 单个分析的导出相同
├── pose/                        （可选）逐帧关键点 CSV
└── pose_dlc/                    （可选）DeepLabCut 格式关键点，可用于 DeepLabCut、SimBA、Keypoint-MoSeq
```
悬尾的 segments 是不动和爬尾的片段，另有逐分钟表；圆筒的 segments 是每次触壁；步态导出步幅表和足印表。
所有汇总表的前 10 列相同（analysis_id、study、animal_id、blind_code、sex、group、timepoint、trial、video、included），可以按 `analysis_id` 关联。任务处于盲法时，动物编号、组别和文件名不会写出（与 iPhone 规则相同）。所有文件为 UTF-8 并带 BOM，Excel 打开中文编号不会乱码；BORIS 和逐帧标签文件不带 BOM。

## 6. 参数：与已发表研究对照

每个分析的检查器最上方有“实验方案”预设。默认值与 iPhone 版完全相同（不会让已有结果变化）；预设只改该方案规定的那几项（时间窗、分相、分箱、回合/步幅规则、关键点置信度），拍摄视角、损伤侧、注射时刻和注射爪保持不变，所有数值照常写入方法学导出。

| 任务 | 预设 | 关键参数 | 来源 |
|---|---|---|---|
| 悬尾 | 6 分钟中的后 4 分钟（默认） | 计分 2:00–6:00 | Can 等 2012 JoVE；UCSF IACUC 标准程序（2025 年 1 月） |
| | 完整 6 分钟 | 0:00–6:00 | Steru 等 1985 |
| 福尔马林 | 0–10 / 10–60 分钟（默认） | 5 分钟分箱 | Mogil 等 1999 |

| | 0–5 / 20–40 分钟 | 小鼠方案 | Nian 等 2014 Bio-protocol |

**我们的判断**：时间窗、分相和分箱属于实验设计，直接采用文献值最合适，也便于和已发表数据比较；体长归一化的速度和距离阈值（如步态 1 体长/秒）依赖相机和动物大小，文献里的 cm/s 只能换算成近似值，所以默认值保持不变，作为预设提供。置信度 0.6 会减少错误位置，但缺口更多，短视频或遮挡多时建议保留 0.3。同一任务里所有动物请用同一个预设（“应用到…”）。

## 7. 验证（在本环境完成的）

- `sh tools/run_core_tests.sh`：在 macOS 命令行或 Linux（Swift 5.10 以上）上编译共享层和 Core 层并运行测试：
  - **检查点**：5000 帧在第 3100 帧处模拟中断（写了一半的行），续跑后与一次跑完的结果逐位相同；`pose.bin` 往返无损；换了视频文件时不会续写旧检查点。
  - **批处理引擎**（用模拟推理器）：6 个视频，同时跑 2 个，中途暂停再继续；1 个坏文件失败并写明原因，1 个出错一次的视频从检查点重试成功，1 个离线视频留在队列里，硬盘接回后完成；任务自动分配和分析；连续两次意外退出后搁置；退出时等待检查点保存后才清空日志。
  - **导出**：所有选项都打开时导出整个资料库，再用 pandas 检查：各表能读取，片段时长 = 结束 − 开始，逐帧标签的 background 列正确，DeepLabCut 文件能用 `header=[0,1,2]` 读出 7 个部位 × (x, y, likelihood)。
  - **半精度转换**：全部 65536 个值与参考结果完全一致。
  - **数据安全**（30 项）：删除视频后文件夹（含复制进来的视频）进入“最近删除”，重新打开资料库也看不到；恢复后视频和分析都回来；只删研究时恢复研究，视频重新归入并保留动物；删除单个分析；立即清除；30 天自动清除；备份写入、列出、恢复（视频备注、纳入决定和分析参数回到备份状态，并先备份当前状态）、自动清理旧备份；资料库锁（另一实例可见、过期忽略、只释放自己的锁）；索引查找在插入、排序、删除后仍然正确。
  - **姿态模型**（21 项）：只提供两个模型（FP16 默认、近红外），CylinderMousePoseV2 只作为旧视频的标签、重新识别改用 FP16、保存过的旧默认值自动改为 FP16；FP16 与旧模型关键点相同；近红外模型的关键点映射（snout→鼻尖、四爪、尾根，无嘴）；26/27/29/30 通道的输出布局识别；旧的 `source.json` 读作旧模型；批处理时每段视频各用自己的模型、`pose.bin` 记录模型名、近红外视频的 QC 正常；用另一个模型重新识别；导出的 `qc_videos.csv`、方法学文字、per_video 摘要和 manifest 都写明模型。
  - **参数预设**：每个预设可重复应用（幂等）、不改每只动物自己的设置、能被识别出当前使用的是哪个预设；悬尾和福尔马林的默认值分别对应“后 4 分钟”和 Mogil 1999。
  - **任务**（35 项）：新建任务（组别去重、去空白；未命名时按范式和日期命名）；文件名 / 文件夹名推测组别；添加 4 段视频后识别前就有 4 个会话、每组 2 个；动物编号自动建档；已分组的动物保持原组别；侧栏一次遍历统计；“未归入任务”的视频移入 / 移出任务及撤销；旧研究分析过两种范式时显示为两个任务；无范式研究变为任务；重启后任务、会话、组别都在；删除任务（保留视频）后视频归入“未归入任务”，撤销后复原；在两个研究的任务之间移动视频不会留下副本或产生多余任务，组别随动物带过去，撤销后恢复原会话；移出任务的视频以文字保留组别、移入新任务后成为动物的组别；删除多范式研究中的一个任务只删除该范式的会话；同一新动物被设为两个组时只建一只动物、取第一个组。
- `sh tools/verify_shared.sh <iPhone 工程的 RodentLimb/RodentLimb 文件夹>`：核对 `Shared/` 与 iPhone 1.4 源码逐字节相同。
- 界面：全部通过语法检查。1.4 的任务页、新建任务、添加视频、移到任务、侧栏、主窗口，以及视频表格、队列、最近删除、研究设计等 30 个界面文件，用模拟 macOS 14 SwiftUI / Charts 接口的替身框架做了类型检查（0 错误），并检查了所有 `store.` / `app.` / `batch.` 成员引用。结果页、播放器、AVFoundation 和 Core ML 部分只做了审阅，**都没有用真实 SDK 编译**。

## 8. 已知限制与下一步

- 两个模型都以 AGPL-3.0（Ultralytics）许可发布（见模型元数据）。如果要在 App Store 上架闭源 App，请先确认许可（Ultralytics 提供企业许可）。

- 本包没有在 Xcode 中编译。第一次编译如果有少量类型错误，按提示修正或发给我。
- 行为评分的局限与 iPhone 版相同：默认阈值来自模拟数据，请先人工评分几段视频再调整参数。
- 暂不支持在 Mac 上实时录制，也不能导出叠加骨架的视频。iPhone 版的“渲染骨架视频”选项在 Mac 上不提供。
- 两端共享代码：`Shared/` 与 iPhone 1.4 源码逐字节相同。以后可以让 iPhone 工程也引用这个文件夹，两端只维护一份分析代码。
